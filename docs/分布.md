# 分布

> 来自一份**不公开的中文语料**，只列分布，不含任何原话。
>
> 这份语料是：一个人和一个 agent 之间、约两周的 5,496 条对话。内容不公开，
> 下面的数字是用仓库里这套代码跑出来的原始统计。

## 总量

| | |
|---|---|
| 条数 | 5,496 |
| 对方 / 我 | 2,427 / 3,069 |
| 时间跨度 | 约两周 |

## 可召回

683 条，占 12%。

拆开来是这样：5,496 条里，1,064 条被判成噪声（直接出局），683 条够格召回，
剩下 3,749 条有效但没到线——通知、复述、跑腿记录、错误日志都在这里。

不是每条话都值得带一辈子。

## 话题分布

| 话题 | 条数 | 占比 | 可召回 | 召回率 | 均分 |
|---|---|---|---|---|---|
| 日常 | 4,053 | 73.7% | 502 | 12.4% | 0.04 |
| 技术 | 1,131 | 20.6% | 93 | 8.2% | 0.01 |
| 项目 | 171 | 3.1% | 18 | 10.5% | 0.03 |
| **情感** | **141** | **2.6%** | **70** | **49.6%** | **0.41** |

## 噪声

判为不可召回的 1,064 条，按原因：

| 原因 | 条数 |
|---|---|
| 代码块 | 635 |
| 太短 | 350 |
| 链接 | 33 |
| 纯符号 | 23 |
| 系统注入 | 18 |
| 无字 | 5 |

## 分数分布（可召回的 683 条）

中位 0.26，上四分位 0.60，最高 1.20。

多数刚过线，少数很突出——长尾，不是均匀分布。

---

## 一个反直觉的数

**情感类只占 2.6%，但其中一半过了线。**

- 情感：141 条 → 70 条可召回（49.6%）
- 技术：1,131 条 → 93 条可召回（8.2%）

同一套规则下，**情感类句子的召回密度是技术类的六倍**。

这就是 `topic_prior` 里「情感 1.3 / 技术 0.5」的根据。不是偏爱情感、
看轻技术，是这份语料本身就长这样：聊技术的句子多，但大多是一次性的操作；
聊到人的句子少，可是几乎每句都算数。

## 边界

这一份语料，不是统计规律。

换一个人、换一种相处方式、换成工作场景，分布会全变——技术话可能才是骨头，
情感话可能全是客套。所以 `topic_prior` 和 `heavy_words` 都是可配置的，
默认值只是起点。

**你自己的数据跑出来什么样，只能自己跑一遍。** 这份文档唯一能保证的，
是告诉你该看哪几个数。
